# 文档导航与使用规则

## 三类资料

| 位置 | 用法 |
| --- | --- |
| [current/](./current/README.md) | **唯一日常工作入口。**固定文件名，随设计和实现修订；写清已实现、待实现和待验证。 |
| [archive/](./archive/README.md) | 旧版、候选稿、评审和交接快照；只用于追溯形成过程。 |
| [validation/](./validation/文档盘点与D1状态核对_2026-10-25.md) | 带日期的构建、核对和运行证据；结论只代表记录时点。 |

## 轻量维护规则

1. 每个主题维护一个固定路径的现行文件；普通技术细化直接更新它，不另建 `v1.2`、`最终版` 或 `最新版`。
2. 当需求范围、角色权限或关键业务规则改变时，在[变更记录](./current/变更记录.md)写原因、受影响的需求/接口/测试和当时验证情况，再同步相关现行文件。普通代码实现细节不需要单独审批文档。
3. 设计是实现目标，不是运行证据。发现设计与代码不同，应更新设计或代码并注明待验证项；不要仅因为旧稿写了“冻结”就继续沿用错误方案。
4. 历史文件中“已冻结”“已确认”记录 2026-10-24 当时的决定。它们保留原样以供毕业设计追溯，不阻止现行文档迭代，也不等于功能、测试或验收完成。
5. 若现行文件内仍有来源版本和冻结日期文字，以文件开头的“现行工作文档”说明及[变更记录](./current/变更记录.md)解释当前使用方式；迁移未改写原始业务决定。
