## 4. 仓库和目录方案

D1 初始化在当前项目根目录 `D:\Graduation Project` 使用单一 Git 仓库；保留已有 `README.md`、`docs/`，并建立源码和运行目录：

```text
D:\Graduation Project\
├── README.md
├── pom.xml                      # Maven reactor root
├── .editorconfig
├── .gitattributes
├── .gitignore
├── .env.example
├── .mvn\wrapper\                 # Maven Wrapper
├── apps\
│   ├── elder-family\             # Uni-app + Vue 3：老人端/子女端
│   └── admin-web\                # Vue 3 + Element Plus + ECharts
├── services\
│   └── api\                       # Spring Boot 单体分层后端
│       └── src\main\resources\db\migration\  # Flyway 版本迁移
├── database\
│   └── seed\                      # 仅含虚构/合成开发数据
├── ops\
│   └── windows\                   # PowerShell 初始化、检查和启动脚本
├── docs\                          # 已有设计基线、追踪与项目文档
└── .local-data\                   # 本机上传文件/临时运行数据，Git 忽略
```

不创建嵌套 Git 仓库。`.local-data/` 和 `.env.local` 不入库；`docs/` 与源码共享同一个版本历史。

## 5. 数据库初始化与迁移

1. 通过本机 MySQL 服务建立独立的演示数据库和最小权限应用账号；数据库名、端口和账号从本地环境变量读取。
2. 首次启动时由 Flyway 从空库执行 `services/api/src/main/resources/db/migration/` 中的有序 SQL 迁移，记录版本和校验值。
3. 已执行的迁移只追加新版本，不直接改写；需要修复时新增迁移脚本并留下变更说明。
4. `database/seed/` 只放虚构/合成的演示初始化数据，和结构迁移分开；重置脚本必须显式指定开发库名并再次确认目标环境。
5. 数据库使用 `utf8mb4`；业务时区遵从总体基线 `Asia/Shanghai`。连接地址、端口、库名和凭据均可配置。

## 6. 配置、文件和启动

- `.env.example` 只提供变量名和非敏感示例；`.env.local`、真实数据库凭据和本机路径加入 `.gitignore`。
- Spring 配置通过 `application-local.yml` 读取环境变量，不在已提交文件写入密码、令牌或个人数据。
- 上传文件写入配置项 `APP_STORAGE_ROOT` 指向的 `.local-data/files/`；数据库只保存文件元数据、校验值和业务关联。仓库源码不承载上传文件。
- Windows 初始化脚本负责检查 JDK/Node/npm/Git/MySQL 版本、建立本地数据目录、提示必需配置，并在缺项时明确报错；不得自动覆盖已有数据库。
- 预定启动方式：后端用 `mvnw.cmd` 启动 `services/api` 的本地配置；两个前端分别执行 `npm ci` 后 `npm run dev`。每个子项目的准确命令在骨架建立时写入根 README。
- Uni-app 使用 DCloud `uni` CLI 工作流；如目标平台要求独立开发者工具，在确认小程序目标平台后列入本机安装清单，不把它误记为后端运行依赖。

## 7. D1 验收门槛

代码仓库建立后，D1 只有满足以下条件才算完成并允许进入共享支撑模块开发：

1. 新克隆目录中可通过仓库脚本核对 Git、JDK、Node、npm、Maven Wrapper 和 MySQL 版本；脚本不依赖开发者个人绝对路径。
2. 按 `.env.example` 建立本地配置后，脚本可检测 MySQL 服务和目标库；不得输出数据库密码。
3. 空白演示库可从头完成 Flyway migration；再次启动不会重复建表，`flyway validate` 通过。
4. 合成种子数据可重复初始化或按说明安全重置；不得连接或覆盖其他库。
5. 后端可启动并通过健康检查；两个前端均可安装锁定依赖并启动/构建。
6. 文件上传目录在首次启动时创建，文件校验和元数据关联可验证；目录不会进入 Git。
7. 干净环境初始化步骤、实际版本和失败处置已写入文档；初始化验证有命令输出或截图留证。
8. 对集成基线中的维护门闩或覆盖全部写入口的等效方案作出 D1 工程决策；决策记录不等于锁序已通过并发验证。

这些是待执行的验收标准，不表示当前仓库、服务或迁移已建立/通过。当前只完成环境盘点和 D1 方案整理。

## 8. D1 后的推进顺序

1. 完成 D1 方案核对，处理 MySQL 8.0.34 的本地环境边界并确认独立演示库参数。
2. 已开始按本方案在项目根目录初始化单仓库和工程骨架；此阶段不写业务模块。
3. 实现最小环境检查、配置模板、Flyway 空库迁移入口和本地启动说明，并执行 D1 验收。
4. D1 通过后建立共享支撑：统一认证上下文、API 错误与追踪、幂等服务、审计和通知 outbox。
5. 补齐 M06 普通工单专项后，按既定依赖顺序推进模块设计、实现和验收。
