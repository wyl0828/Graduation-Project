# 2026-10-27 业务变更记录

本文件记录 2026-10-27 针对社区工作人员账号与角色管理体系、护工本人工单履约工作流及工程入口安全守卫的业务与架构决策变更。

## 变更明细

### CR-20261027-01: 社区工作人员账号与角色细粒度管理体系 (M01)
- **变更背景**：
  社区管理员原无法在线维护本社区工作人员账号并分配 `COMMUNITY_ADMIN`、`GRID_MEMBER`、`CARE_WORKER` 角色，缺少员工账号生命周期管理（创建、修改角色、重置密码、停用/启用）；且原架构缺少管理员角色调整时的活跃会话撤销能力，存在降权或停用后旧 Token 仍能越权操作的安全风险。
- **决定与改动**：
  - 在后端 `modules/auth` 新增 `StaffManagementController` 与 `StaffManagementServiceImpl`，提供工作人员列表分页查询、创建员工、分配调整角色、重置初始密码、切换启用状态（启用/停用）接口；
  - 强化越权与自保护校验：严格限定操作范围为管理员所属 `communityId`；禁止管理员自撤销最后一个有效管理员角色；
  - 会话联动安全撤销：在员工角色变更或停用时，自动将其全部活跃 Session/Token 加入黑名单（`auth_session` 即时失效），阻断旧会话，要求重新登录；
  - 初始密码线下交付：创建或重置密码时由管理员设定，禁止通过系统日志、审计明文暴露；
  - 前端 `apps/admin-web` 新增 `StaffRoleManagementView.vue`（路由 `/staff/roles`），左侧菜单根据角色权限动态过滤，普通网格员或护工访问自动 403 拦截。
- **影响范围**：
  - 模块：`services/api/src/main/java/cn/communityelderly/modules/auth`
  - 接口：`GET /api/v1/auth/staff`、`POST /api/v1/auth/staff`、`PUT /api/v1/auth/staff/{userId}/roles`、`PUT /api/v1/auth/staff/{userId}/status`、`POST /api/v1/auth/staff/{userId}/reset-password`
  - 前端：`apps/admin-web/src/views/staff/StaffRoleManagementView.vue`、`AdminLayout.vue`、`router/index.ts`、`api/adminApi.ts`
  - 现行文档更新：[接口契约 M01/M02](../current/接口契约_M01_M02.md)、[运行指南](../current/运行指南.md)、[需求与范围](../current/需求与范围.md)、[批次 1 数据入口与授权边界验收记录](../validation/批次1-数据入口与授权边界验收记录_2026-10-27.md)

### CR-20261027-02: 护工本人分配工单履约工作流与并发冲突防护 (M06/M07/M08)
- **变更背景**：
  此前工单状态流转主要面向全社区范围管理员与网格员操作，护工角色（`CARE_WORKER`）缺乏专属工作台，存在查看全社区长辈档案的越权风险；且在工单接单、开始、提交等状态迁移并发时，缺乏细粒度冲突（409 Conflict）处理，容易导致操作日志污染或状态覆盖。
- **决定与改动**：
  - 严格限定 `CARE_WORKER` 的查询与执行边界：只能查看并操作分配给自己（`care_worker_id == currentUserId`）且属于本社区的未结工单；护工登录直接重定向至工单执行台，无权访问长辈档案列表与数据看板；
  - 完整实现履约闭环：工单接单（`DISPATCHED -> ACCEPTED`）、开始服务（`ACCEPTED -> IN_SERVICE`）、上传现场照片凭证、提交结案（`IN_SERVICE -> PENDING_REVIEW`）；
  - 引入乐观锁（`row_version`）与状态机冲突控制：并发抢单、重复接单或已被改派时，接口拒绝并返回 HTTP 409 Conflict，不产生额外成功的操作日志或错误更新；
  - 配合 Flyway 迁移 `V3_3__work_order_photo_evidence.sql` 支持履约图片留痕。
- **影响范围**：
  - 模块：`services/api/src/main/java/cn/communityelderly/modules/order`
  - 接口：`GET /api/v1/orders/work-orders/my-assignments`、`POST /api/v1/orders/work-orders/{id}/accept`、`POST /api/v1/orders/work-orders/{id}/start`、`POST /api/v1/orders/work-orders/{id}/submit`、`POST /api/v1/orders/files/upload`
  - 前端：`apps/admin-web/src/views/order/WorkOrderExecutionView.vue`
  - 现行文档更新：[接口契约 M01/M02](../current/接口契约_M01_M02.md)、[项目计划](../current/项目计划.md)、[批次 1 数据入口与授权边界验收记录](../validation/批次1-数据入口与授权边界验收记录_2026-10-27.md)

### CR-20261027-03: 工程入口安全防护与首次种子数据并发事务保护 (ops)
- **变更背景**：
  本地启动、测试和演示修复脚本若在未配置或缺少关键环境变量时运行，容易引发不可预期的数据库写入或连接非目标库；同时，首次演示种子装载缺乏并发防护与失败原子回滚机制。
- **决定与改动**：
  - `start-api.ps1`、`run-test.ps1`、`repair-demo-activation.ps1`、`repair-demo-passwords.ps1` 均增加严格的环境检查与目标拒绝：若未配置 `.env.local`、缺少数据库凭据、或指定非目标库，在调用 Maven/MySQL 外部进程前立即 fail-closed 退出；
  - 强化 `load-demo-seed.ps1`：仅允许向空白的 `elderly_care_demo` 执行一次性导入，装载过程全程纳入事务，失败自动回滚；增加并发额外行检测与提交后异常提示；
  - 新增独立守卫测试套件 `Test-DemoDbGuard.ps1`，创建临时 loopback MySQL 自动化校验上述错误拒绝与并发保护机制。
- **影响范围**：
  - 运维脚本：`ops/windows/`
