# 社区居家养老系统审查问题修复 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 消除本轮审查确认的认证与越权、关键操作假成功、数据脚本误操作风险，并用真实端到端证据重新核定阶段状态。

**Architecture:** 服务端以数据库当前会话、当前角色与对象关系为唯一授权依据；关键写操作在同一事务内完成状态校验、幂等与审计。前端由一个明确的数据源入口发请求，只有服务器确认后才能呈现业务成功；Mock 仅用于显式原型模式。演示重置与正常种子导入分离。

**Tech Stack:** Spring Boot 3.5、Java 17、MyBatis-Plus、MySQL 8/Flyway、Uni-app/Vue 3、Vue 管理端、PowerShell。

**Spec:** `docs/current/需求与范围.md`（尤其 BR-07/10/11、FR-M01/M03/M04/M05/M06/M07/M09/M12、AT-15/27/33/35/36/37/38–41）、`docs/current/跨模块设计.md`、`docs/current/项目计划.md`。本轮问题及运行证据见发起此计划的代码审查会话。

## Global Constraints

- 只对隔离的 `elderly_care_demo` 和合成数据运行写入、重置与并发验证；不得把现有本机演示库当作可随意清空的临时库。
- 所有业务日期使用 `Asia/Shanghai`，服务端时间为权威；取消、审批、结案等状态变化必须保留历史与审计。
- 未授权、关系非 `ACTIVE`、跨社区、无效状态和未知会话均拒绝；不能以默认用户或默认老人 ID 兜底。
- 当前工作区已有大量未提交文件；开始每批前记录精确状态，显式选择文件，不执行 `git add .`，不自动提交或推送。
- 修订 `docs/current/` 现行文档；保留历史验收记录原貌。不能把服务层测试、构建成功或 Mock 操作写成 HTTP、真机或端到端通过。

## Review Focus

1. 未登录、过期、撤销、停用账号或已撤销角色发起请求，应得到 401/403 且无业务副作用（Task 2）。
2. 同一用户跨老人、跨社区、亲情冻结或解绑后重试访问，应被拒绝且不泄露详情（Task 3）。
3. 同键同内容重试返回首次结果；同键异内容、并发竞争和非法状态跳转不得创建第二事实（Task 4）。
4. API 断网、401、409、500 时，SOS、服药和工单页面不得显示成功或改变持久业务状态（Task 6）。
5. 错库、缺密码、导入中断或文件恢复失败时，脚本必须拒绝或保留可恢复快照，不能报告“校验通过”（Task 1、Task 12）。

1. **先封住风险：** Task 1–3 完成并通过负例测试前，不开放真实联调给其他用户。
