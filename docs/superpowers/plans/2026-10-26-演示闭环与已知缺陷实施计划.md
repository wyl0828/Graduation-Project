# 演示闭环与已知缺陷 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让小程序用户能安全退出并切换演示账号，修复管理端已复现的告警流 404 和静态检查错误，再以隔离数据完成四角色页面及关键写入验收。

**Architecture:** 小程序沿用现有 Bearer 会话和服务端 `POST /api/v1/auth/logout`；注销成功或服务端已判定会话失效后清除本地身份与亲情上下文，再重启到登录页。管理端沿用现有 API 封装与后端 `/dashboard/community/alerts-feed` 契约，页面只展示已取得的服务端数据，并明确加载、空数据和请求失败。验收统一使用临时 MySQL 与合成账号，不写入正在使用的演示库。

**Tech Stack:** Java 17 / Spring Boot 3.5、MySQL 8、Uni-app / Vue 3 / TypeScript、Vue 3 / Element Plus / ECharts、PowerShell、Playwright CLI。

**Spec:** `docs/current/需求与范围.md`（AT-01、AT-09、AT-38、AT-41）、`docs/current/接口契约_M01_M02.md`、`docs/current/项目计划.md`；本轮失败证据见 `docs/validation/全面测试记录_2026-10-26.md`。

## Global Constraints

- 以当前 `D:\Graduation Project` 工作区为对象；开始每项前记录 `git status --short`，保留已有未跟踪文件，不自动提交或推送。
- 业务写入只针对脚本创建的独立临时 MySQL 与合成数据；不得清空、重播种或用失败场景污染现有本机演示库。
- 注销必须使服务端 token 失效。网络失败或服务端 5xx 时保留当前会话并提示重试；收到 401 表示会话已失效，可清理本地状态。
- 前端不得把静态占位统计、接口 404/500 或未完成的写操作显示为实时数据或成功。
- 微信开发者工具与真机结果分别记录；H5、构建、真实 HTTP 与真机不能互相替代。

## Review Focus

1. 连点“退出登录”只发一次注销请求，取消确认不改变会话（Task 1）。
2. 注销后旧 token 再请求受保护接口返回 401；换账号后不闪现上一个账号的长辈资料（Task 1、4）。
3. 注销网络失败时给出可重试提示，不假装服务端已撤销 token（Task 1）。
4. 大屏告警流空列表、404/500、部分接口失败时显示对应状态，刷新不得提示“全部同步成功”（Task 2、4）。
5. 仿真注入在状态未加载、加载中、无管理员角色时拒绝进入提交路径（Task 3、4）。
