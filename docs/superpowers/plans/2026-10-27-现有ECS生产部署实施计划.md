# 现有 ECS 生产部署 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将当前社区居家养老服务系统部署到现有 `120.26.248.237` ECS，停止但不删除 MewHelp 项目，并通过 `https://aimianshi.xyz/` 对外提供可验证的管理端、H5 与 API。

**Architecture:** 在本机完成 Spring Boot JAR、管理端和 H5 的构建，服务器仅运行 Nginx 与两个独立 Docker 容器（API、MySQL）。管理端部署在站点根路径，H5 部署在 `/h5/`，Nginx 将 `/api/` 和 `/actuator/health` 反代到仅监听 `127.0.0.1:8080` 的 API 映射端口。原 MewHelp systemd 服务和容器停止、禁用开机自启并保留 `/opt/mewhelp` 数据与配置，部署失败时可恢复。

**Tech Stack:** Spring Boot 3 / Java 17、MySQL 8、Vue 3 / Vite、uni-app H5、Docker Compose、Nginx、Let's Encrypt

**Spec:** `README.md`、`docs/current/运行指南.md` 与用户 2026-10-27 的部署请求

## Global Constraints

- 目标服务器固定为 `root@120.26.248.237`，域名固定为 `aimianshi.xyz`；使用现有有效 HTTPS 证书。
- 不删除 `/opt/mewhelp`、MewHelp Docker bind mount、镜像或历史备份；仅停止并禁用 MewHelp 应用和基础设施单元。
- 保留 SSH、Nginx、Docker、系统监控及时间同步等基础服务。
- 新系统写入 `/opt/community-elderly`，持久化数据库和上传文件不得放在发布目录内。
- 数据库、应用账号及 HMAC 密钥在服务器端随机生成，配置文件权限为 `600`，不得写入仓库或命令输出。
- 上线前必须有本轮后端测试、两个前端构建和产物检查；上线后必须有容器、健康接口、HTTPS 页面与静态资源验证。
- 当前工作区的文档与论文改动属于用户；部署只取应用源码、数据库迁移和种子，不覆盖、不提交这些改动。

## Review Focus

- MewHelp 停止后仍可通过保留的 systemd 单元、`/opt/mewhelp` 和 bind mount 恢复。
- API 容器只能通过宿主机回环端口访问，MySQL 不向公网暴露。
- Nginx 的 SPA fallback 不得吞掉 `/api/`、`/actuator/health` 或 ACME challenge。
- H5 `/h5/` 子路径的脚本、样式和前端路由资源必须返回 200，API 仍使用同源 `/api/v1`。
- Cookie 在 HTTPS 下使用 Secure，登录与 CSRF 流程不能因反向代理头或路径切换失效。
