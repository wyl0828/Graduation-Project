## 2. 现在坏掉的（必须先处理，否则演示不了）

### 2.1 【最紧急】演示库无人能登录——密码哈希没迁移

- 代码现在**只接受 BCrypt**（`AuthServiceImpl:346` 的正则 + `passwordEncoder.matches`），不认识的旧哈希一律拒绝。
- 但当前 `elderly_care_demo` 库里的 6 个账号仍是旧种子写入的假哈希：

```
1  13800000001  PBKDF2v1$600…
2  13800000002  PBKDF2v1$600…
…（全部 6 个）
```

- 【实测】`13800000001` + 正确口令 `Admin123456` → **401**。
- 而新的种子 SQL 已经是"**仅首次加载**"：`load-demo-seed.ps1` 会检查 40 余张表必须全空，当前库非空 → **直接拒绝执行**。
- 结论：**现在没有任何受支持的路径把旧库的哈希换成新哈希**。计划里 Task 12 的"受控重置"还没做。
- 建议（二选一，都很小）：
  1. 加一个**只改密码哈希**的幂等脚本/迁移：`UPDATE sys_user SET password_hash='<新 BCrypt>' WHERE phone_normalized=… AND password_hash NOT LIKE '$2%'`；
  2. 或允许 `load-demo-seed.ps1 -Reset` 走"快照 + 清空 + 重灌"的受控路径（计划 Task 12 本来就要做）。

### 2.3 前端完全没有跟进，现在连不上后端

- `apps/admin-web/src/api/http.ts:12` **仍然是** `localStorage.getItem('token') || 'demo-admin-token'`。
- `router/index.ts` 仍无 `/login`、无守卫；`apps/admin-web/src/views/` 下仍没有登录页。
- 结果：管理端每个请求都带 `demo-admin-token` → 后端现在**一律 401** → 管理端 10 个页面全部失效。
- 小程序 `login.vue` 仍不调后端、不存 token → 同样全部 401。
- 另外新增了一个**传输方式耦合**，前端改造时必须注意（否则会踩坑）：
  - `AuthenticationFilter:49-51` 要求 **Cookie 会话必须是 `WEB` 客户端**、**Bearer 会话必须是 `MINIAPP` 客户端**；
  - 所以管理端以后**必须改成 Cookie + `X-CSRF-Token`**，不能再用 `Authorization: Bearer`；用 Bearer 走 WEB 登录会被判 401。
  - `AUTH_COOKIE_SECURE` 默认 **true**，而本地是 `http://127.0.0.1:5173`；`.env.local` 里还没设这个变量。落地登录页前建议先确认本地 Cookie 能否写入（必要时本地设 `AUTH_COOKIE_SECURE=false`）。

## 4. 新增代码里值得注意的几点（不是回退，但要盯住）

1. **每个请求都写库**：`AuthSessionAuthenticationService:90-93` 每次认证都 `updateById(lastActivityAt)`（通知轮询除外）。功能正确，但一个页面加载 10 个接口就是 10 次写；并发演示时要注意。
2. **`@RequireRoles` 缺失时只校验"登录"**：`RoleAuthorizationInterceptor:44-46` 在无注解时直接放行。这正是 F-04b 仍然存在的原因；建议反过来——对 `/api/v1/**` 默认要求"至少一个显式角色"，只对真正的公开只读接口开白名单。
3. **`GET /api/v1/service-catalogs` 现在也需要登录**：小程序在未登录时拉服务目录会 401，需确认这是否是期望行为。
4. **`AuthRateLimitService` 的 HMAC 密钥为空时抛 `AUTH_CONFIGURATION_UNAVAILABLE`**：`.env.local` 已配 64 位十六进制，但**新环境必须记得配**，否则所有登录 500/业务异常。
5. **测试环境入口变了**：`./mvnw test` 不再可用（无 `DB_PASSWORD`），必须走 `./ops/windows/run-test.ps1`。这一点应写进 README/工程基座，否则下一个人会以为代码坏了。
