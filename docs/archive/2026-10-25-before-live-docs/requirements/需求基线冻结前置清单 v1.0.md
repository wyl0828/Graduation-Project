## 1. 使用规则

### 1.1 状态定义

| 状态       | 含义                                                                         |
|------------|------------------------------------------------------------------------------|
| 待决策     | 业务规则尚未得到明确批准；必须确定规则，或经确认列为非本期范围并说明边界。   |
| 待同步     | 业务决定已有依据，但 SRS、总体设计、需求矩阵或验收场景仍有旧表述。           |
| 待专项设计 | 业务方向已确认，数据库、API、状态迁移、事务、并发或部署方案尚未定稿。        |
| 待验收     | 已有验收目标，但尚无可复现的执行结果和证据。                                 |
| 已关闭     | 仅在决策依据、文档同步或测试证据实际具备后填写；不得根据“评审收口”自动关闭。 |

### 1.2 冻结原则

1.  **需求冻结不等于功能完成。** SRS
    可以在实现前冻结，但每个业务规则必须有确定结论或明确的非本期边界。
2.  **不把建议升级为已确认规则。** G-01—G-24、C-04/C-06/C-07、N-01/M-01/S-01 及 FZ-01—FZ-03 已有明确批准或非本期结论；其他仍标为“建议”的本期行为，须取得决定或写明排除边界后才能成为冻结规则。
3.  **业务规则与技术实现分开。**
    业务状态、权限、异常结果及验收判据须明确；物理表结构、接口字段、锁、事务与重试方案可以进入专项设计。
4.  **非本期事项必须写明影响。**
    至少记录排除原因、用户可见行为、替代处理方式、涉及模块/需求编号，以及未来重新纳入的条件。
5.  **验收目标不等于验收通过。** AT-36、AT-38—AT-41
    等必须保留“未测/通过/失败”真实状态和证据位置。
6.  本清单中的 P0/P1
    是本轮建议的处理优先级，不是源文档已经批准的优先级。

- [x] **G-05｜E05 激活码特殊签发流程｜已决策 2026-10-24**
  - **决定：** 默认当面向老人交付，可在老人本人在场时协助输入。特殊签发须核验老人身份及合法代理权限并记录原因、方式、操作者和结果；无法核验不签发。未使用的疑似泄露码立即作废重签；已使用则走账号恢复。工作人员不得代替老人完成身份关联。
- [x] **G-06｜Q02-EX01 档案重新启用与业务恢复｜已决策 2026-10-24**
  - **决定：** 本社区管理员按原因办理并审计。只恢复未来应生成的任务和常规提醒；不补造停用期任务、不补发过期提醒。已生成当日任务仅可在截止前正常确认；过窗任务保持未确认状态。
