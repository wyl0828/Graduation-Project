## 实现与失败反馈边界

- 服务端以认证主体、操作路由和 `Idempotency-Key` 唯一约束持久化 `PROCESSING`/`COMPLETED` 状态及请求摘要。请求摘要含方法、实际 URI、查询参数和规范化 JSON 正文；同键异体冲突不会覆盖原记录。
- 只有取得占位所有权的请求可以完成记录；过期接管通过条件更新和 owner token 阻止旧处理尝试覆盖新所有者。
- 2xx 与可重放的终态 JSON 4xx 保存原状态和正文。5xx、非 JSON/超大响应及完成记录失败时保持 fail-closed，不放行同键重复业务执行。
- 管理端与老人端只为已标注的关键写入请求发送幂等头，包括 SOS 取消；正文变化会生成新键。可重试的网络错误、401、409 和服务器错误会保留同一请求键并把原错误交给页面；带幂等头的 401 不触发全局强制跳转，使页面保留表单和错误状态。管理端 409 提示保留服务端原始错误消息。
- 对写成功后需要 GET 回读确认的管理端操作，页面在状态确认前保留键；回读失败或状态不符时，同一表单重试复用同一键，确认后清除。普通写请求在 2xx 后清键。
- 老人首页 SOS 和药盒失败时显示具体错误并保留待处理内容；药盒请求仅在服务端确认打卡后清除待处理计数，不再提前显示成功。

## 未测边界

- 浏览器中的待处理幂等键保存在内存；刷新页面或重启客户端会丢失尚未确认请求的本地键与输入。本轮未覆盖刷新后的恢复体验。
- 并发集成用例覆盖同一键的处理中冲突；未进行不同键竞争、并发压力或吞吐量测试。
- 本轮执行 H5 与微信小程序构建，没有在微信开发者工具、Android/iOS 真机或真实管理端浏览器中走查交互。
- 工单拒单及管理员预约拒绝目前没有管理端 API helper/页面；这些 required-key 路由仍由服务端保护，管理员预约确认由隔离 HTTP 链使用请求头覆盖，拒单与预约拒绝的 UI 流程未测。
- 不涉及真实短信/验证码；完整 Maven 入口中的 4 个认证门控测试跳过，按 Task 2 记录由独立临时库入口单独验收。
