## 本批次覆盖

- 用药行为测试使用固定 `Asia/Shanghai` 时钟，核验 UTC 日期边界、按提醒槽补齐当日缺项、暂停期不补造且恢复后只生成当前日任务、INACTIVE 老人不补建任务或发送新的关怀通知，以及计划更新时旧版本结束日与新版本生效日衔接。HTTP 链同时验证今日任务读取和同键打卡重放。
- 待确认预约由原申请人直接取消且不生成工单；已确认、未接单预约进入管理员队列。批准会在同一事务内取消预约并终止尚未接单的工单，保存申请人、审核人、审核时间和原因；拒绝保留预约与待派工单并生成审核记录和逻辑通知。
- 真实并发测试覆盖接单与取消审批竞争，断言只出现一个合法结果。服务中止覆盖申请资格、管理员审核、已完成/未完成内容与后续计划留痕、预约及工单状态联动、人员/时间记录和同键审核重放。
- 预约有效时段唯一键保留在 `V3_2` 生成列上；`REJECTED`、`CANCELLED`、`SERVICE_STOPPED` 释放时段。`V3_9` 为当前读增加组合索引，数据库集成测试覆盖三种终态后的同槽重约以及 RR 旧快照并发冲突。
- 撤销护工角色时产生待交接记录、操作历史、审计和去重通知，保留工单承接人、状态和进度；旧会话请求被拒。档案停用只接受最新交接记录为 `ACCEPTED` 且接收人为当前承接人的未结工单；测试覆盖 B 接手后再次撤权时拒绝停档、C 接手后才允许停档。
- 老人档案停用与创建预约的 RR 当前读并发测试验证：若关联未结工单在停用事务等待期间提交，停用仍会被拒。停用后的普通预约创建/确认均被拒且没有业务副作用。
- 跨日用药固定时钟测试覆盖停机补建、暂停/恢复、当日槽补齐和 INACTIVE 老人不生成普通新任务/关怀通知；SOS 测试与 HTTP 链验证停用快照持久化及管理员列表可见。
- 本次完整 HTTP 链还通过现有预约履约、SOS 处置、会话改密/停用/注销和亲情关系失效检查，保证新增链路未破坏这些相邻行为。
