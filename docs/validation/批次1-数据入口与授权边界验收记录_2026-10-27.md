## HTTP 与数据库矩阵

- 匿名请求员工列表/创建为 401；网格员请求员工列表、创建、换角为 403；缺少 `Idempotency-Key`、短密码、未知/运维角色、家庭角色混用均在写入前拒绝，数据库、会话和审计快照不变。
- 管理员不能撤销本社区最后一个有效管理员；跨社区角色替换为 404 且角色、会话、审计事实不变。创建仅返回脱敏字段；审计包含 actor、community、target、前后角色和原因，不包含密码。
- 允许 `COMMUNITY_ADMIN + GRID_WORKER` 与 `COMMUNITY_ADMIN + CARE_WORKER`；拒绝 `GRID_WORKER + CARE_WORKER`。角色变更撤销目标的 Web Cookie 和 MINIAPP Bearer 会话；重新授予角色后旧凭据仍返回 401。
- 预置 `FAMILY` 的 `CHILD + ELDER` 账号切换后保留相互独立的亲情关系和老人本人身份范围。该夹具只用于授权边界验收，不调用短信或激活接口。
- 护工只可查看本人当前分配且未终结的工单；接单、开始服务、绑定 `workOrderId` 上传并提交结果成功。终态、非承接人、改派前承接人、跨社区工单和缺少 `workOrderId` 的访问在文件写入前拒绝；档案、社区看板仍拒绝。失败请求的业务快照和隔离文件数不变。
- 工单乐观锁更新 0 行时，护工接单、开始、提交现返回 `OPTIMISTIC_LOCK_CONFLICT`（HTTP 409），并在写操作历史前中止；回归单测覆盖三条路径。
- 同轮保留六个契约合成账号、Web Cookie/CSRF、老人资料与药盒、子女关系与预约、管理员派单、网格员履约、管理员审核、SOS 处置和注销旧令牌等既有控制链。

## 浏览器 smoke

最终运行的阶段标签：

`ADMIN_LOGIN_OK → STAFF_CREATE_CARE_HTTP_201 → STAFF_CREATE_ADMIN_HTTP_201 → DISPATCH_HTTP_200 → ADMIN_LOGOUT_HTTP_200 → SELF_ADMIN_LOGIN_OK → SELF_REVOKE_HTTP_200 → CARE_LOGIN_OK → CARE_ACCEPT_OK → CARE_START_OK → CARE_UPLOAD_OK → CARE_SUBMIT_OK → CARE_LOGOUT_HTTP_200 → GRID_LOGIN_OK → GRID_DIRECT_ROUTE_BLOCKED_TO_WORKER_HOME → GRID_STAFF_ROUTE_NOT_VISIBLE`

管理员从 UI 创建护工与管理员账号、派单并验证自撤权；护工 UI 完成接单、开始、上传及提交；网格员登录后直接访问员工管理路由被拦截。每次角色登录前清理浏览器 Cookie 与本地会话存储。登出后浏览器 Cookie 缺失、本地认证状态清空，`/auth/current-user` 返回 401。

首次浏览器运行在网格员登录页导航阶段超时；验收 helper 随后改为每个角色登录前重置 Cookie/storage，并避免已经位于 `/login` 时重复导航。对已含测试夹具的同一临时库重跑未作为通过证据；最终结果来自全新隔离数据库，脚本报告中没有 HTTP 或 JUnit 失败。
