## 目标与当前基线

项目目标是交付可复现、可演示且权限与业务状态可信的社区居家养老系统。当前**未提交共享工作区**已在独立临时 MySQL 上完成 Flyway V1–V3.3、合成种子、员工/角色授权、护工本人分配工单执行，以及既有服药、预约、SOS 和注销 HTTP 主链。最近一次完整 Maven 为 176 项（172 通过、0 失败/错误、4 个环境跳过）；最终浏览器 smoke 覆盖管理员建号/自撤权、护工履约和网格员路由拒绝。另一次独立守卫验证证明启动、测试、演示修复入口会在调用 Maven/MySQL 前拒绝缺失配置和错误目标，首次种子装载的事务与并发保护通过。具体边界见上述两份批次 1 记录。以上不代表批次 1 整体完成、干净检出、部署环境、微信真机或 M01–M12 全项验收。

## 当前优先任务

1. **收尾批次 1（下一步）**：执行临界到期、停用/改密/角色失效、亲情 `ACTIVE/PENDING/FROZEN/UNLINKED`、同社区无绑定、跨对象和跨社区的真实 HTTP 正负矩阵；补跑当前因 `AUTH_TEST_DB_URL` 门控跳过的 4 个认证数据库用例。每个拒绝场景都要比较请求前后的业务、会话、通知和审计事实。
2. **推进批次 2**：实现共享 `Idempotency-Key` 的请求摘要、原状态码/响应体重放与跨重启持久化；覆盖 SOS、预约、工单、告警并发竞争及页面在断网、401、409、500 下的真实状态。当前仅护工接单、开始和提交的乐观锁冲突已有 409 回归证据。
3. **完成业务边界与可信证据**：按顺序处理跨日用药、确认后取消/服务中止/责任交接，再完成文件实际内容与业务归属、审计完整性，以及 Q09-04/AT-37“首次有效接单时间减创建时间”的固定数据手算验收。
4. **交付验收**：仅在前述必要缺口关闭后，验证已使用演示库的安全重置、数据库与文件联合备份恢复、干净检出、微信开发者工具/真机、至少 5 名非开发者适老化走查和固定规模性能。

已完成的窄范围包括：社区约束亲情关系列表与可校验 ID、看板社区隔离和空样本口径、社区员工账号/角色管理、护工本人当前分配工单执行，以及工程入口/首次种子保护。完成证据以带日期的验证记录为准，不能据此推导整个批次或全部 AT 通过。

没有短信服务时，手机号找回、子女注册与老人首次激活保持安全关闭；引入可信核验渠道后再规划启用及验收。
