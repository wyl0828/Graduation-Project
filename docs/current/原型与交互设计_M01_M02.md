## 1. 业务范围与角色分流架构

### 1.1 账号体系与四角色入口映射

系统采用**统一账号体系与双端分离入口**，业务账号分为 `FAMILY`（家庭用户）与 `STAFF`（工作人员）两大独立体系，严格禁止跨体系兼任：

```mermaid
flowchart TD
    subgraph AppEntry["统一入口与凭证识别"]
        MiniApp["小程序端入口<br/>(Uni-app: 微信小程序/H5)"]
        WebAdmin["Web 管理端入口<br/>(Vue 3 + Element Plus)"]
        AuthBackend["后端统一认证服务 (/api/v1/auth/login)"]
    end

    subgraph FamilyAccounts["家庭账号体系 (account_kind = FAMILY)"]
        ElderRole["老人角色 (ELDER)<br/>入口：小程序老人模式"]
        ChildRole["子女角色 (CHILD)<br/>入口：小程序子女模式"]
    end

    subgraph StaffAccounts["工作人员体系 (account_kind = STAFF)"]
        GridWorker["网格员/护工 (GRID_WORKER/CARE_WORKER)<br/>入口：Web 工作台"]
        AdminRole["社区管理员 (COMMUNITY_ADMIN)<br/>入口：Web 管理后台"]
    end

    MiniApp -->|手机号+密码 / 激活码| AuthBackend
    WebAdmin -->|手机号+密码 + 安全 Cookie| AuthBackend

    AuthBackend -->|颁发 Bearer Token| MiniApp
    AuthBackend -->|写入 HttpOnly Cookie| WebAdmin

    AuthBackend -->|识别身份| FamilyAccounts
    AuthBackend -->|识别身份| StaffAccounts

    ElderRole <-->|允许同账号兼任<br/>上下文独立切换| ChildRole
    GridWorker <-->|允许岗位兼任<br/>执行与审核分离| AdminRole
```

* **老人角色（`ELDER`）**：由社区管理员先建立业务档案，老人凭 6 位一次性激活码首次激活账号并完成身份关联。界面为大字适老模式。
* **子女角色（`CHILD`）**：支持自主注册，未通过社区管理员亲情绑定核验前，无权访问任何老人健康或业务数据。
* **双角色兼任（老人 + 子女）**：允许同一手机号账号兼有 `ELDER` 和 `CHILD` 角色。两种模式的页面数据上下文严格隔离，切换入口时重新向服务端请求当前角色权限，不自动互通数据。
* **网格员 / 护工（`GRID_WORKER` / `CARE_WORKER`）**：由社区管理员分配，仅能查看分配给本人的工单及执行所需脱敏信息。
* **社区管理员（`COMMUNITY_ADMIN`）**：负责本社区的老人建档、激活码签发、亲情绑定审批、争议冻结及工单调度。
* **系统运维人员**：独立运维身份，不分配为业务角色，默认禁止直接通过业务界面浏览老人健康或亲情隐私数据。

### 1.2 会话时限与自动撤销规则

| 客户端环境 | 空闲超时时限 | 绝对有效时限 | 自动失效/撤销条件 |
| :--- | :--- | :--- | :--- |
| **Web 管理端** | 30 分钟无操作 | 12 小时 | 密码重置、换号成功、角色变更、主动退出、账号停用 |
| **小程序端** | 7 天无操作 | 30 天 | 密码重置、换号成功、角色变更、主动退出、账号停用 |

*注：静默短轮询、心跳或查询不延长空闲时限；解绑或冻结亲情关系立即撤销对应老人的数据访问权限，但不强制退出子女账号。*

## 2. 核心状态流转图（Mermaid）

### 2.1 老人 6 位一次性激活码生命周期状态机

激活码是老人档案关联登录账号的安全凭据，生命周期如下：

```mermaid
stateDiagram-v2
    [*] --> ISSUED: 管理员当面/受控核验后签发<br/>(生成6位随机码, 有效期24h)
    
    ISSUED --> USED: 老人输入正确激活码 + 手机号验证<br/>(同事务关联 elder_id 与 user_id)
    ISSUED --> LOCKED: 连续输错 5 次激活码<br/>(防爆破锁死, 不可再试)
    ISSUED --> EXPIRED: 超过 24 小时未消费
    ISSUED --> SUPERSEDED: 管理员重新签发新码<br/>(旧码同事务作废)
    
    LOCKED --> SUPERSEDED: 管理员重新核验并重签
    EXPIRED --> SUPERSEDED: 管理员重新签发
    
    USED --> [*]: 关联建立成功, 码不可复用
    SUPERSEDED --> [*]: 废弃归档
```

### 2.2 亲情绑定与授权关系生命周期状态机

亲情关系是子女访问老人数据的唯一合法授权依据，状态流转如下：

```mermaid
stateDiagram-v2
    [*] --> PENDING: 子女端提交绑定申请<br/>(记录老人标识、亲属关系、证明事由)
    
    PENDING --> ACTIVE: 社区管理员核验批准<br/>(核验亲属关系及老人意愿)
    PENDING --> REJECTED: 社区管理员拒绝<br/>(填写真实拒绝原因, 留痕)
    
    ACTIVE --> UNLINKED: 子女主动解除 / 老人解除指定绑定<br/>(即时失权, 历史数据保留)
    ACTIVE --> FROZEN: 管理员设置争议冻结<br/>(疑似冒用/亲属争议, 5工作日内复核)
    ACTIVE --> REVOKED: 管理员依据充分正式撤销<br/>(失权并记录撤销原因)
    
    FROZEN --> ACTIVE: 复核查实无误, 有据恢复
    FROZEN --> REVOKED: 复核确认违规/失效, 正式撤销
    
    REJECTED --> PENDING: 补充材料重新申请
    UNLINKED --> PENDING: 再次申请重新走核验
    REVOKED --> PENDING: 原撤销原因已消除且提供新依据
```

### 2.3 老人档案状态机

```mermaid
stateDiagram-v2
    [*] --> ACTIVE: 社区管理员核验建档完成
    ACTIVE --> INACTIVE: 管理员按原因停用<br/>(前置检查: 未结工单必须已结案或完成交接)
    INACTIVE --> ACTIVE: 社区管理员按原因重新启用<br/>(恢复档案, 恢复未来用药计划生成)
    
    note right of INACTIVE
      停用边界:
      1. 禁止一般新业务(预约、体征补录、新服药任务)
      2. 窄范围保留: 有效老人账号仍可发起 SOS
      3. 既有告警与停档前体征异步评估继续处理
    end note
```

### 2.4 档案更正申请闭环状态机（FZ-01）

```mermaid
stateDiagram-v2
    [*] --> PENDING_REVIEW: 有效未冻结子女提交更正申请<br/>(固化目标字段当前基线快照 baseline_value)
    
    PENDING_REVIEW --> APPROVED_APPLIED: 管理员核验通过<br/>(单事务内: 校验baseline无冲突, 更新档案, 写审计)
    PENDING_REVIEW --> REJECTED: 管理员填写原因拒绝
    
    APPROVED_APPLIED --> [*]
    REJECTED --> [*]
```

## 4. 完整的交互四态定义

| 交互状态 | 适用场景 | 小程序端视觉与交互表现 | Web 管理端视觉与交互表现 |
| :--- | :--- | :--- | :--- |
| **空态 (Empty)** | • 子女端尚未绑定任何老人<br/>• 管理员待审核绑定列表为空<br/>• 更正申请列表为空 | 居中展示温和友好的插画与大字提示：“暂无监护的老人”，正下方提供主操作大按钮：“+ 申请绑定老人”。 | 表格区域居中展示 Element Plus 空状态组件（`el-empty`），提示“暂无待处理的亲情绑定申请”，无多余干扰。 |
| **加载态 (Loading)** | • 登录与激活校验网络请求<br/>• 亲情申请提交中<br/>• 切换老人加载数据中 | 页面覆盖半透明遮罩与大尺寸 Loading 动效，主按钮置灰禁用并显示“正在处理中，请稍候...”，**严格阻止重复点击**。 | 表格区域展示骨架屏或局部 `v-loading` 转圈动效，操作按钮置为 `loading=true` 状态，禁止重复提交表单。 |
| **失败态 (Error)** | • 激活码输错（剩余次数提醒）<br/>• 激活码连续 5 次输错锁死<br/>• 登录密码错误<br/>• 更正申请并发冲突 (409) | • 激活码错误：输入框红色边框抖动，提示“激活码错误，还剩 X 次重试机会”；<br/>• 锁死：大红色告警卡片提示“该激活码已失效，请联系社区重新签发”；<br/>• 冲突：轻提示弹窗“老人资料在此期间已被更新，请刷新重试”。 | 页面顶部弹出持久警示条或表单字段下方标红错误文本，对于 409 状态冲突弹窗提示具体冲突字段并提供“刷新最新数据”快捷按钮。 |
| **无权 / 冻结拦截态 (Unauthorized / Frozen Interception)** | • 亲情绑定为 `PENDING`（审核中）<br/>• 亲情绑定为 `FROZEN`（争议冻结）<br/>• 亲情绑定已 `UNLINKED` 或 `REVOKED`<br/>• 老人档案处于 `INACTIVE`（已停用）<br/>• 会话过期 (401) | • **审核中拦截**：页面展示时钟图标黄色提示框：“亲情绑定申请正在社区审核中，暂无法查看健康与用药数据”；<br/>• **冻结拦截**：警示黄/橙色卡片：“监护关系已被社区临时冻结（复核中），访问权限已暂停，如有疑问请联系社区管理员”；<br/>• **档案停用**：老人端顶部横幅提示“档案已暂停”，除 **SOS 紧急求助按钮**保持可用外，其他业务按钮均置灰禁用；<br/>• **401 过期**：自动清空本地 token，弹窗提示“登录已过期，请重新登录”，点击确定平滑返回登录页。 | • **无权拦截**：页面提示 `403` 无权限访问当前社区或对象，严禁透露未授权老人敏感内容；<br/>• **401 过期**：自动清除 Cookie/会话，跳转回后台登录页并携带 `redirect` 参数。 |

## 5. 交互落地与验收映射（对应验收测试 AT）

本交互规格直接覆盖下列需求与验收场景：
* **AT-01 / AT-15**：四角色登录与会话失效边界（P-01, P-02）；
* **AT-14**：老人 6 位激活码签发、错误 5 次锁死、重签作废旧码与激活绑定闭环（P-04, P-05）；
* **AT-02 / AT-20**：亲情关系申请、审批、解绑失权、争议冻结与多老人切换隔离（P-08, P-09, P-10）；
* **AT-18**：老人档案建立、字段缺失原因联动与档案本人维护（P-03, P-06）；
* **AT-18 (FZ-01)**：档案更正申请提交、快照比对、并发冲突与原子审批（P-11, P-12）；
* **AT-16**：密码找回与人工核验重置（P-13）。
