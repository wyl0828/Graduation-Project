## 1. 已确认边界与当前缺口

首期使用 **Uni-app + Vue 3 的一个小程序工程**，提供老人和子女两种模式，共用后端身份、请求封装及必要基础组件。老人可查看本人健康、用药、SOS、帮助和服务进度；子女仅在当前有效亲情授权范围内查看老人资料、维护用药计划及申请服务。总体设计中的 P1—P5 是核心页面范围参考，不限制登录、绑定、表单、详情和反馈页面的必要数量。

当前 `apps/elder-family/` 已有 DCloud Vue 3/Vite TypeScript 骨架、锁文件、入口占位页及 H5/微信小程序编译结果；微信 AppID 已配置，尚无老人/子女业务页面、微信开发者工具或真机运行证据。下述业务目录仍是后续实现候选，不能把占位页视为模块完成。

## 2. 候选目录与职责

```text
apps/elder-family/
├── package.json、依赖锁文件
└── src/
    ├── App.vue、main.ts、pages.json、manifest.json、uni.scss
    ├── pages/
    │   ├── auth/           登录、注册、首次激活与恢复
    │   ├── elder/          大字首页、任务、SOS、进度、帮助
    │   ├── family/         监护首页、老人详情、计划、预约、亲情关系
    │   └── account/        个人中心与身份切换
    ├── components/
    │   ├── common/         加载、空态、失败与确认反馈
    │   └── elder/          大按钮、状态卡片、文字及语音帮助
    ├── api/                uni.request 封装及按业务划分的接口
    ├── stores/             会话、当前身份和当前授权对象的页面上下文
    ├── types/              请求、响应和视图类型
    ├── utils/              展示时间、同次操作幂等键等纯辅助函数
    └── static/             图标、图片及受控音频资源
```

`pages/` 负责界面与操作路径；`api/` 只负责与已冻结端点契约通信；`stores/` 保存有限的界面上下文。子女当前选择的老人 ID 只是查询上下文，不是授权凭据。通用组件不包含亲情授权、服药或 SOS 的业务裁决。服务端每次按账号、角色、档案状态、对象归属和当前亲情关系重新判断权限，前端隐藏按钮只改善体验。

页面组织建议先覆盖总体设计 P1—P5，再按可执行操作补登录/激活、关系申请、计划编辑、预约表单、任务详情和结果页。完整导航、字段、加载/空/成功/失败状态须另形成交互说明；此目录图不等于原型完成。

## 3. 会话、身份与请求边界

1. 手机号加密码登录，登录后从服务端获取当前可用身份与对象权限。兼任老人和子女身份时，两种模式的页面数据上下文分开；切换模式重新取当前权限，不自动复用另一个身份的数据。会话无操作及绝对期限沿 SRS 已批准边界，凭据存储、刷新与撤销细节留 M01 契约冻结。
2. `api/http` 统一处理服务地址、会话凭据、`/api/v1`、`traceId`、响应体和 HTTP/业务错误；业务 API 文件只声明具体请求。客户端不直接展示服务端堆栈，也不记录密码、令牌或不必要健康信息。
3. 会创建业务事实、推进状态或触发副作用的请求沿集成基线使用 `Idempotency-Key`。同一次网络重试复用原键和同一规范化输入；一次新的真实 SOS 或新的业务操作使用新键。同键异内容冲突不得静默重新提交。
4. 超时或断网后的结果是“未确认成功”，应提供查询原结果或同键安全重试路径；不能在本地推断业务已提交。角色变更、解绑或授权冻结后，相关页面数据应失效并重新向服务端获取，服务端拒绝须明确反馈。
5. 所有业务日期与截止以服务端按 `Asia/Shanghai` 判定的结果为准；前端负责清晰显示，不用本机时钟决定打卡或预约是否最终可接受。

## 4. 老人端关键交互

| 操作 | 必须保持的业务语义 | 需设计的页面状态 |
| --- | --- | --- |
| SOS 长按 | 满 2 秒才发送，不足 2 秒松开不发；成功只表示服务器已接受，不能显示已接单或到场。 | 按压进度、提交中、接受成功、结果未确认、明确拒绝及备用联系方式。 |
| 服药任务与本人确认 | 当日任务在原提醒前可用；提前确认须明确声明已实际服用。截止后不开放普通历史补打，过窗不称为漏服。 | 未到提醒、可提前确认、已到提醒、已确认、超过普通打卡窗口、加载/错误。 |
| 服务进度 | 使用 M06 权威记录；“已接单”不能显示成“已到达”。 | 有工单、无工单、加载失败、当前无权查询。 |
| 帮助与语音 | 语音失败时，文字仍能完成 SOS、打卡和必要查询。 | 音频可用/不可用及等价文字操作。 |

老人模式正文默认至少 18 CSS px，主要触控目标至少 48×48 CSS px，SOS 主操作至少 64×64 CSS px；状态不能只靠颜色表达。页面需在 360 CSS px 视口检查截断、重叠和反馈，随后按 AT-38/39 在目标开发者工具及 Android/iOS 实机留证。以上均是**验收目标，尚未实测**。

## 5. 子女端关键边界

子女注册或登录不自动获得老人数据；经核验的亲情关系及其当前状态决定访问。亲情冻结、解绑、账号停用后，列表、详情、统计、文件和写入均须由服务端立即拒绝。子女可在有效授权范围内维护用药计划，但不得代替老人打卡或发起 SOS；仅原申请人可按当前预约状态发起允许的取消/中止流程。跨老人切换须清空上一对象的敏感页面状态并重新加载；缓存策略在模块 API 和安全设计中确定。
