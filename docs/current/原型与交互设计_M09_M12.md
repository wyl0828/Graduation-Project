## 2. M09 社区态势感知与数据看板设计

### 2.1 页面架构与视觉布局
看板由顶部控制栏、KPI、三类图表和实时事件流组成。趋势当前只提供服务端实际计算的近 7 天范围；无有效分母的比率显示“无数据”，查询错误显示独立错误状态。设计稿示意值只表达版式，不代表运行数据。

```
+---------------------------------------------------------------------------------------+
|  [顶部控制栏] 社区范围: [当前账号授权社区]  趋势范围: [近 7 天]  [立即刷新]  [全屏]         |
+---------------------------------------------------------------------------------------+
|  [核心指标 KPI 胶囊卡片]                                                                |
|  [接口数量或 0] 辖区长辈总数   [接口数量或 0] 待处理预警/SOS                              |
|  [接口比率或无数据] 助老工单履约率 [接口比率或无数据] 长辈慢病用药合规率                    |
+---------------------------------------------------+-----------------------------------+
|  [图表 A: 慢病画像分布；零计数时显示“暂无数据”]    |  [图表 B: 服务构成；零计数时显示空态]|
+---------------------------------------------------+-----------------------------------+
|  [图表 C: 近 7 天工单走势与平均响应时长 (复合折线柱状图)]                             |
|  柱状: 每日派单量 vs 完工结案量；无工单时显示“暂无数据”                                |
+---------------------------------------------------+-----------------------------------+
|  [模块 D: 实时安全预警与 SOS 态势动态流 (实时列表墙)]                                 |
|  服务端事件摘要、时间和处置状态；空列表、加载中与请求失败分别显示对应状态                |
+---------------------------------------------------------------------------------------+
```

当前前端仍显示社区选择控件，但看板接口按登录用户的社区权限确定数据范围，改变该控件不改变服务端查询范围；在社区切换契约接通前，不应把该控件解释为已实现的数据筛选。近 30 天和本年度趋势也未由后端实现，当前界面只标注近 7 天。

`avgResponseMinutes` 按 Q09-04 计算当日创建工单从创建到首次有效接单的平均分钟数：普通工单取首次合法 `ACCEPT` 历史，SOS 工单取触发时的自动接单历史；不使用可覆盖的 `accept_time` 或服务起止时间。统计使用 Asia/Shanghai 自然日左闭右开分桶，均值保留一位小数，无有效样本返回 `null` 并显示“无数据”。AT-37 已以两个社区固定数据完成手算与隔离集成验收，记录见 [批次4验收记录](../validation/批次4-证据统计与审计验收记录_2026-10-28.md)。

### 2.2 核心图表交互与内存防泄漏规范
1. **ECharts 响应式与资源释放**：
   - 监听窗口 `resize` 事件，统一调用 `chartInstance.resize()`；
   - 在 Vue 3 组件 `onUnmounted` 阶段必须显式调用 `chartInstance.dispose()`，杜绝页面切换引发的内存泄漏。
2. **主题适配与大字清晰度**：
   - 数据标签采用加粗高对比度字号，适配大屏投屏显示与领导视察场景。

## 3. M12 全局安全审计日志工作台设计

### 3.1 页面架构与检索矩阵
系统所有涉及权责变更、人身安全、隐私调整的关键操作均被物理落库至 `audit_log`：
- **筛选维度**：
  - 操作模块/目标类型：`全部`、`ELDER_PROFILE (老人档案)`、`FAMILY_LINK (亲情关系)`、`WORK_ORDER (助老工单)`、`MEDICATION_PLAN (用药档案)`、`HEALTH_ALERT (预警处置)`；
  - 动作类型：`CREATE`、`UPDATE`、`APPROVE`、`REJECT`、`FREEZE`、`EXEMPTION (免照审核)`；
  - 操作人角色：`社区管理员`、`网格员`、`子女`、`SYSTEM (系统任务)`；
  - 全局 TraceId 快速精准定位；
- **列表关键展示字段**：
  - 发生时间（精确到毫秒）、操作人账号与角色、目标实体与业务主键、动作名称、执行结果（成功/阻断）、客户端来源 IP、全局链路 TraceId、快照比对按钮。

### 3.2 敏感数据变更对比抽屉 (Diff Viewer)
点击操作行的“查看变更快照”时，滑出右侧宽抽屉：
- **左右对照视图**：
  - 左侧：**变更前基线快照 (`before_json`)**；
  - 右侧：**变更后提交快照 (`after_json`)**；
- **典型合规比对场景**：
  1. **档案更正冲突 (FZ-01)**：原监护人电话 `13800000001` vs 变更后 `13800000009`，标红对比。
  2. **工单免拍照特殊结案**：展示网格员填写的免照豁免原因快照，以及审核管理员账号 ID，杜绝违规代签。
  3. **亲情关系争议冻结 (FZ-02)**：展示争议原因与冻结时段，留存法律存证依据。
