## 1. 契约约定与全局规范

### 1.1 通信协议与路由规范
* **协议与基础路径**：所有业务 API 统一使用 HTTPS（本地开发支持 HTTP），路由强制采用 `/api/v1` 前缀。
* **数据格式**：请求体与响应体默认统一使用 `application/json;charset=UTF-8`。
* **时间与日期标准**：
  * 时间戳瞬间采用 ISO-8601 格式带时区（如 `2026-10-25T14:30:00+08:00`）；
  * 业务日期采用 `YYYY-MM-DD`（如 `1952-05-18`），业务时区统一为 `Asia/Shanghai`，服务端时钟为绝对权威。

### 1.2 统一响应报文结构

#### (1) 通用成功响应（HTTP 200 / 201）
```json
{
  "code": "OK",
  "message": "操作成功",
  "traceId": "trace-4a9b-8f1c-20261025143000",
  "data": { ... }
}
```

#### (2) 通用分页列表响应（HTTP 200）
`page` 从 1 开始，`pageSize` 默认 10，上限 50。
```json
{
  "code": "OK",
  "message": "查询成功",
  "traceId": "trace-4a9b-8f1c-20261025143000",
  "data": {
    "items": [ ... ],
    "page": 1,
    "pageSize": 10,
    "total": 35
  }
}
```

#### (3) 通用业务错误响应（HTTP 4xx / 5xx）
```json
{
  "code": "INVALID_CREDENTIALS",
  "message": "手机号或密码错误",
  "traceId": "trace-4a9b-8f1c-20261025143000",
  "data": null
}
```

### 1.3 链路追踪与响应头
* 服务端在过滤器或拦截器中优先提取请求头 `X-Trace-Id`（若无则自动生成 UUID）；
* 服务端响应头必须附带 `X-Trace-Id: <traceId>`，与 JSON 报文中的 `traceId` 保持一致，贯穿业务日志与审计。

### 1.4 身份认证与凭证传递
* **Web 管理端**：登录成功后由服务端写入 `HttpOnly; Secure; SameSite=Lax` Cookie（名称 `SESSION_TOKEN`），前端状态写请求需在请求头携带 `X-CSRF-Token`；
* **小程序端**：登录成功后返回 `token`，小程序在后续所有受保护请求的 Header 中携带：
  `Authorization: Bearer <token>`
* **权限隐藏防枚举原则**：对于未登录请求返回 `401 AUTHENTICATION_REQUIRED`；对于无权访问或不存在的数据，统一返回 `404 RESOURCE_NOT_FOUND_OR_NOT_ACCESSIBLE`，严禁通过替换 ID 探测其他老人或家庭隐私。

### 1.5 幂等控制规范 (`Idempotency-Key`)
所有具有副作用或状态迁移的 POST/PUT/PATCH 请求必须携带请求头：
`Idempotency-Key: <UUID 或业务幂等标识>`
* **同键同请求内容**：服务端直接重放此前已提交的原业务响应，不重复执行写事务；
* **同键异请求内容**：服务端立即拒绝并返回 `HTTP 409 IDEMPOTENCY_KEY_REUSED`，记录安全审计。

### 1.6 乐观并发控制与冲突响应规范

对 `elder_profile`、`elder_family_link`、`elder_correction_request` 等聚合根的修改请求，必须携带 `expectedVersion`。

#### (1) 普通版本冲突（HTTP 409 `OPTIMISTIC_LOCK_CONFLICT`）
当数据库最新版本与 `expectedVersion` 不符时返回：
```json
{
  "code": "OPTIMISTIC_LOCK_CONFLICT",
  "message": "数据已被其他操作更新，请刷新重试",
  "traceId": "trace-conflict-001",
  "data": {
    "currentVersion": 2,
    "expectedVersion": 1
  }
}
```

#### (2) 档案更正基线快照冲突（HTTP 409 `FIELD_VALUE_CONFLICT`）
审批档案更正申请时，若目标字段在申请提交后已被其他人修改（数据库当前值 ≠ `baseline_value`），整单阻断并返回冲突明细，供管理员核验比对：
```json
{
  "code": "FIELD_VALUE_CONFLICT",
  "message": "老人档案字段在此期间已被更新，更正申请基线已失效",
  "traceId": "trace-conflict-002",
  "data": {
    "conflicts": [
      {
        "fieldCode": "address",
        "baselineValue": "朝阳社区幸福路12号院3号楼2单元101",
        "currentDatabaseValue": "朝阳社区幸福路12号院3号楼3单元201",
        "proposedValue": "朝阳社区幸福路12号院3号楼4单元502"
      }
    ]
  }
}
```

### 1.7 多老人上下文显式传递规范
子女端在切换监护老人时，**目标 `elderId` 一律通过 URL 路径参数显式传递**（如 `/api/v1/elders/{elderId}/...`），严禁依靠会话全局隐式绑定：
* 服务端接收到包含 `{elderId}` 的请求时，必须在过滤器/拦截器中实时执行二次鉴权：
  1. 校验当前登录账号有效；
  2. 校验当前账号对该 `elderId` 是否存在状态为 **`ACTIVE`** 且未冻结的 `elder_family_link`；
  3. 若关系处于 `FROZEN`，直接拦截并返回 `403 FAMILY_LINK_FROZEN`；若关系处于 `PENDING`，返回 `403 FAMILY_LINK_PENDING`；若不存在或已解绑，返回 `404 RESOURCE_NOT_FOUND_OR_NOT_ACCESSIBLE`。

## 2. 权限矩阵与社区范围隔离规则

### 2.1 角色定义与代码
* `COMMUNITY_ADMIN`：社区管理员（隶属于具体 `community_id`）
* `GRID_WORKER` / `CARE_WORKER`：网格员 / 护工（隶属于具体 `community_id`）

## 3. 核心 API 端点详细契约

### 3.1 身份认证与会话管理 (M01)

#### 1. 统一用户登录 `POST /api/v1/auth/login`
* **权限**：公开匿名
* **请求 Header**：`Content-Type: application/json`
* **请求体**：
```json
{
  "phone": "13800000001",
  "password": "Admin123456",
  "clientType": "WEB" // "WEB" 或 "MINIAPP"
}
```
* **响应报文 (HTTP 200)**：
```json
{
  "code": "OK",
  "message": "登录成功",
  "traceId": "trace-login-001",
  "data": {
    "userId": 1,
    "phone": "13800000001",
    "accountKind": "STAFF",
    "token": "token_string_only_for_miniapp", // Web端通过Set-Cookie下发
    "csrfToken": "csrf_token_string_for_web",
    "roles": [
      {
        "roleCode": "COMMUNITY_ADMIN",
        "roleName": "社区管理员",
        "communityId": 1,
        "communityName": "朝阳社区"
      }
    ],
    "currentRole": "COMMUNITY_ADMIN"
  }
}
```

#### 2. 用户登出 `POST /api/v1/auth/logout`
* **权限**：登录用户
* **响应报文 (HTTP 200)**：
```json
{
  "code": "OK",
  "message": "已成功退出当前会话",
  "traceId": "trace-logout-001",
  "data": null
}
```

#### 3. 子女端自主注册 `POST /api/v1/auth/register-child`
* **当前状态**：没有可信短信服务，接口安全关闭。下方为目标契约示意，不能按固定码执行。
* **权限**：公开匿名
* **请求 Header**：`Idempotency-Key: <UUID>`
* **请求体**：
```json
{
  "phone": "<未注册测试手机号>",
  "smsCode": "<真实核验所得验证码>",
  "password": "<新密码>"
}
```
* **响应报文 (HTTP 201)**：
```json
{
  "code": "OK",
  "message": "注册成功",
  "traceId": "trace-reg-001",
  "data": {
    "userId": 4,
    "phone": "13800000004",
    "roleCode": "CHILD",
    "token": "bearer_token_sample"
  }
}
```

#### 4. 老人凭 6 位激活码首次激活账号 `POST /api/v1/auth/activate-elder`
* **当前状态**：没有可信手机号控制权核验，接口安全关闭。下方为历史目标契约示意，实际字段和启用条件须在接入核验服务时重新校准。
* **权限**：公开匿名（老人首次开通）
* **请求 Header**：`Idempotency-Key: <UUID>`
* **请求体**：
```json
{
  "ticketId": "<未过期票据>",
  "activationCode": "<一次性激活码>",
  "phone": "<已验证手机号>",
  "smsCode": "<真实核验所得验证码>",
  "password": "<新密码>"
}
```
* **业务逻辑与异常**：
  * 若码错误，返回 `400 TICKET_CODE_MISMATCH`，`data.remainingAttempts` 返回剩余可用尝试次数；
  * 若连续输错 5 次，状态置为 `LOCKED`，返回 `403 TICKET_LOCKED`；
  * 若超过 24 小时，返回 `400 TICKET_EXPIRED`；
  * 若成功，单事务创建 `sys_user`、分配 `ELDER` 角色、创建 `elder_identity_link`，激活码状态置为 `USED`。
* **响应报文 (HTTP 200)**：
```json
{
  "code": "OK",
  "message": "老人身份激活成功，已完成账号关联",
  "traceId": "trace-act-001",
  "data": {
    "userId": 7,
    "elderId": 2,
    "elderName": "李秀英",
    "archiveNo": "ARC202610250002",
    "token": "bearer_token_elder"
  }
}
```

### 3.2 社区工作人员账号与角色管理 (M01)

以下接口供本社区管理员创建和管理工作人员账号。社区范围、操作者和账号类型均由服务端当前会话及业务规则确定，客户端不得提交 `communityId`、`grantedBy`、`accountKind` 或会话操作者 ID。家庭身份仍由既有的子女注册与老人激活流程建立，员工接口不得分配 `ELDER` 或 `CHILD`。

角色组合仅允许单独分配 `COMMUNITY_ADMIN`、`GRID_WORKER` 或 `CARE_WORKER`，以及 `COMMUNITY_ADMIN` 与其中一种工作人员角色兼任；拒绝 `GRID_WORKER + CARE_WORKER`、家庭角色、运维角色、未知角色及重复角色。工作人员手机号必须为规范化 11 位手机号；初始密码至少 8 个字符并符合 BCrypt 的 72 字节上限，服务端保存 BCrypt 哈希。

本节的“有效管理员”须同时满足：本社区 `COMMUNITY_ADMIN` 角色分配为 `ACTIVE`，且关联账号为 `STAFF`、账号状态为 `ACTIVE`。

**幂等边界：**写接口要求 `Idempotency-Key`，但当前共享拦截器只阻止重复 key，不会重放已成功响应。同键同内容响应重放及跨服务重启持久化属于 Batch 2 的共享幂等缺口，仍待修复；本节接口不声明已实现该全局语义。

#### 1. 查询本社区工作人员 `GET /api/v1/admin/staff`

* **权限**：`COMMUNITY_ADMIN`；只返回当前会话所属社区内有工作人员角色分配历史的 `STAFF` 账号。
* **成功响应**：`data` 为员工摘要数组。已撤销本社区全部角色的账号仍保留在列表中，`roleCodes` 为空；角色摘要只包含当前有效角色。

```json
{
  "code": "OK",
  "message": "操作成功",
  "traceId": "trace-staff-list-001",
  "data": [
    {
      "userId": 42,
      "maskedPhone": "138****0042",
      "accountStatus": "ACTIVE",
      "roleCodes": ["GRID_WORKER"]
    }
  ]
}
```

#### 2. 创建工作人员账号 `POST /api/v1/admin/staff`

* **权限**：`COMMUNITY_ADMIN`。
* **请求头**：必填 `Idempotency-Key`。
* **请求体**：仅接受手机号、管理员设置的初始密码和角色代码。

```json
{
  "phone": "13800000042",
  "initialPassword": "InitialPass123",
  "roles": ["GRID_WORKER"]
}
```

* **原子行为**：验证手机号唯一、初始密码及允许角色；创建 `STAFF` 账号、在当前社区分配请求角色并写入成功审计，三者同一事务提交。审计记录操作者、目标用户、社区、动作 `STAFF_CREATED` 和角色摘要，不含手机号或密码明文。
* **成功响应 (HTTP 201)**：返回员工摘要，不返回密码、哈希或明文手机号。

```json
{
  "code": "OK",
  "message": "操作成功",
  "traceId": "trace-staff-create-001",
  "data": {
    "userId": 42,
    "maskedPhone": "138****0042",
    "accountStatus": "ACTIVE",
    "roleCodes": ["GRID_WORKER"]
  }
}
```

#### 3. 替换当前社区角色 `PUT /api/v1/admin/staff/{userId}/roles`

* **权限**：`COMMUNITY_ADMIN`；只允许修改当前社区内的工作人员账号。目标不存在、不是工作人员账号或不属于当前社区时统一返回 `404 RESOURCE_NOT_FOUND_OR_NOT_ACCESSIBLE`。
* **请求头**：必填 `Idempotency-Key`。
* **请求体**：`roles` 是该员工在当前社区的完整角色集合；空数组表示撤销其在当前社区的全部工作人员角色，保留账号和分配历史。每次撤销必须填写原因。

```json
{
  "roles": [],
  "reason": "员工离岗，撤销本社区工作人员权限"
}
```

* **成功行为**：新增角色写入新的有效分配行；撤销角色将原分配更新为 `REVOKED` 并记录 `revokedAt`、`revokedBy`、`revokeReason`。至少保留一名本社区有效管理员（角色分配与关联 STAFF 账号均为 `ACTIVE`）。角色集合实际改变时，同一事务撤销目标账号全部 Web 与小程序会话，原因 `ROLE_CHANGED`，并写入 `STAFF_ROLES_REPLACED` 审计（含变更前后角色和原因，不含密码及完整手机号）。已撤销会话的旧令牌不会因后续重新授予角色而重新有效，员工须重新登录。提交的集合与当前集合相同时按无变更处理，不撤销会话。
* **成功响应 (HTTP 200)**：返回更新后的员工摘要。

#### 工作人员接口错误与拒绝语义

| HTTP 状态 | 错误码 | 含义 |
| ---: | --- | --- |
| 400 | `BAD_REQUEST` | 手机号/密码格式错误、密码不足8个字符、角色不在允许集合、角色组合非法、撤销未填写原因或尝试移除本社区最后一个有效管理员 |
| 401 | `AUTHENTICATION_REQUIRED` | 未登录或会话已失效 |
| 403 | `ACCESS_DENIED` | 当前角色不是 `COMMUNITY_ADMIN` |
| 404 | `RESOURCE_NOT_FOUND_OR_NOT_ACCESSIBLE` | 目标账号不存在、不是 `STAFF` 或不属于当前社区 |
| 409 | `PHONE_NUMBER_EXISTS` | 手机号已被其他账号使用 |
| 409 | `OPTIMISTIC_LOCK_CONFLICT` | 目标角色分配在更新期间已变化 |

### 3.5 老人档案更正申请闭环 (M02 / FZ-01)

#### 1. 子女提交档案更正申请 `POST /api/v1/elders/{elderId}/correction-requests`
* **权限**：`CHILD`（必须是与该老人处于 `ACTIVE` 且未冻结的有效亲情绑定）
* **请求 Header**：`Idempotency-Key: <UUID>`
* **请求体**：
```json
{
  "reason": "父亲搬迁至同小区3单元201室，且紧急联系电话变更为工作手机",
  "items": [
    {
      "fieldCode": "address",
      "proposedValue": "朝阳社区幸福路12号院3号楼3单元201"
    },
    {
      "fieldCode": "emergency_contact_phone",
      "proposedValue": "13900000004"
    }
  ]
}
```
* **服务端原子行为**：
  * 读取当前数据库中该老人的当前字段值，自动固化为 `baseline_value_protected` 快照写入明细表；
  * 状态置为 `PENDING_REVIEW`，不修改档案本身。
* **响应报文 (HTTP 201)**：
```json
{
  "code": "OK",
  "message": "档案更正申请已提交，等待社区核验",
  "traceId": "trace-corr-req-001",
  "data": {
    "requestId": 1,
    "status": "PENDING_REVIEW"
  }
}
```

#### 2. 管理员审批并原子应用档案更正 `POST /api/v1/admin/correction-requests/{requestId}/review`
* **权限**：`COMMUNITY_ADMIN`
* **请求 Header**：`Idempotency-Key: <UUID>`
* **请求体**：
```json
{
  "decision": "APPROVE", // "APPROVE" 或 "REJECT"
  "decisionReason": "经与老人电话核验地址与联系人变动属实，予以更新"
}
```
* **服务端基线比对与原子应用逻辑**：
  1. 开启单数据库事务，排他锁锁定老人档案与更正申请明细；
  2. 逐项比对 `elder_profile` 字段当前值是否与申请提交时的 `baseline_value_protected` 一致；
  3. **若任一字段发生改变**：事务回滚，记录阻断 `block_code = 'FIELD_VALUE_CONFLICT'`，返回 HTTP 409 `FIELD_VALUE_CONFLICT`；
  4. **若全部一致且通过**：将 `proposed_value` 写入 `elder_profile`，递增档案 `row_version`，在明细表记录 `before_value` 和 `after_value`，申请状态更新为 `APPROVED_APPLIED`，同事务记录领域事件与操作审计。
* **响应报文 (HTTP 200)**：
```json
{
  "code": "OK",
  "message": "档案更正申请已批准并成功应用",
  "traceId": "trace-corr-apply-001",
  "data": {
    "requestId": 1,
    "status": "APPROVED_APPLIED",
    "updatedArchiveVersion": 2
  }
}
```

## 4. 业务错误码与前端“四态”映射字典

| HTTP 状态 | 业务错误代码 (code) | 默认错误提示 (message) | 前端界面呈现类型 | 前端交互行为与操作指引 |
| :---: | :--- | :--- | :---: | :--- |
| **400** | `VALIDATION_ERROR` | 请求参数格式错误 | **失败态** | 表单对应输入框下方标红，提示具体校验错误 |
| **400** | `TICKET_CODE_MISMATCH` | 激活码错误，请重新输入 | **失败态** | 激活码输入格震动抖动，提示“激活码错误，还剩 X 次重试机会” |
| **400** | `TICKET_EXPIRED` | 激活码已过期 (超过24小时) | **失败态** | 提示“激活码已过期失效，请联系社区重新签发” |
| **401** | `AUTHENTICATION_REQUIRED` | 需要身份认证 | **拦截态** | 清空本地过期 Token，平滑跳转登录页并记录 redirect |
| **401** | `SESSION_EXPIRED` | 登录会话已超时过期 | **拦截态** | 弹窗轻提示“会话已过期，请重新登录”，确认后跳转 |
| **401** | `INVALID_CREDENTIALS` | 手机号或密码错误 | **失败态** | 登录按钮解除 Loading，输入框显示红色提示文案 |
| **403** | `TICKET_LOCKED` | 连续输错5次，激活码已锁死 | **拦截态** | 醒目红色卡片，禁止继续输入，指引“请联系社区网格员重签” |
| **403** | `FAMILY_LINK_PENDING` | 亲情关系正在社区审核中 | **拦截态** | 首页展示黄色时钟卡片“亲情审核中”，阻断查看体征与用药 |
| **403** | `FAMILY_LINK_FROZEN` | 亲情监护关系已被临时冻结 | **拦截态** | 橙色警示卡片：“监护关系已被社区临时冻结，访问权限暂停” |
| **403** | `ACTION_NOT_ALLOWED` | 当前角色无权执行此操作 | **失败态** | 弹窗提示无权操作，禁止界面按钮动作 |
| **404** | `RESOURCE_NOT_FOUND_OR_NOT_ACCESSIBLE` | 对象不存在或无权访问 | **空态 / 失败态** | 不泄露数据是否存在，呈现“未找到相关信息”占位 |
| **409** | `IDEMPOTENCY_KEY_REUSED` | 相同幂等键携带不同内容 | **失败态** | 提示“请勿重复提交冲突的请求，请刷新后重试” |
| **409** | `OPTIMISTIC_LOCK_CONFLICT` | 数据已被其他人更新 | **失败态** | 提示“数据已被更新，请刷新重试”，提供“刷新最新数据”按钮 |
| **409** | `FIELD_VALUE_CONFLICT` | 档案更正基线快照冲突 | **失败态** | 管理员后台标红高亮冲突字段，禁止静默覆盖 |
| **429** | `AUTH_COOLDOWN` / `RATE_LIMITED` | 操作过于频繁，请稍候重试 | **失败态** | 倒计时禁用按钮，提示“请等待 X 秒后再试” |
