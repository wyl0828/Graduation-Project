# 第 5 章 系统实现

## 5.1 受助与监护端功能实现

移动端小程序采用 Uni-app + Vue 3 开发，构建产物运行于微信小程序环境。系统依据用户身份和选定视图，提供针对老年群体的“适老模式”与针对监护家属的“子女模式”。

### 5.1.1 老人适老主页与极简服药打卡实现

#### 1. 适老化界面交互实现
老人模式下，主页采用无衬线大号字体与高色度对比度的卡片式布局，主色调选用易于识别的暖色系与深底色。系统通过全局 CSS 变量统一控制适老字号与触控热区：
```css
/* 适老化根级视觉约束规范 */
.elder-theme {
  --font-size-title: 24px;       /* 标题字号 */
  --font-size-content: 18px;     /* 正文字号 */
  --font-size-sub: 16px;         /* 辅助字号 */
  --touch-min-height: 56px;      /* 最小触控热区高度 */
  --contrast-color: #1a1a1a;     /* 高对比度文本 */
  --bg-primary-btn: #2d8cf0;     /* 高纯度按钮底色 */
}
```

#### 2. 服药计划展示与打卡流转
老人登录后，客户端自动请求 `/api/v1/medication/tasks/today`，后端聚合生成当日早、中、晚三个时段的服药任务清单。
- 未打卡时，卡片呈现醒目的黄色待办状态；
- 老人点击“确认服药”大按钮后，触发 Web Audio 播放语音提示“已为您记录服药”，同时前端发起打卡请求：
```typescript
// 服药打卡逻辑实现
async function handleCheckin(taskId: number) {
  try {
    uni.vibrateShort({ type: 'medium' }); // 物理触觉震动反馈
    await api.medication.checkin({
      taskId: taskId,
      checkinTime: new Date().toISOString(),
      actionType: 'NORMAL'
    });
    uni.showToast({ title: '服药已记录', icon: 'success' });
    refreshTodayTasks();
  } catch (err) {
    uni.showToast({ title: '网络异常，请重试', icon: 'none' });
  }
}
```

### 5.1.2 一键突发 SOS 紧急求助实现

一键 SOS 是保障独居老人生命安全的最高优先级功能，常驻于小程序主屏右下方悬浮层。

#### 1. 防误触倒计时机制
为防止老年人因手指颤抖发生误触，点击红色的“SOS 紧急求助”后，系统弹出占据全屏 80% 的二次倒计时遮罩层，默认倒计时 3 秒。若老人在 3 秒内未点击“取消求助”，倒计时结束立即调用后端紧急求助接口。

#### 2. 服务端原子建单核心实现
服务端在接收到求助请求后，在单个数据库事务内完成紧急告警落库与紧急工单初始化：
```java
@Transactional(rollbackFor = Exception.class)
public WorkOrder triggerSosEmergency(Long elderId, String remark) {
    ElderProfile elder = elderProfileMapper.selectById(elderId);
    if (elder == null) {
        throw new BusinessException(ErrorCode.RECORD_NOT_FOUND, "老人档案不存在");
    }

    // 1. 持久化突发 SOS 告警事件
    SosEvent event = new SosEvent();
    event.setElderId(elderId);
    event.setCommunityId(elder.getCommunityId());
    event.setStatus("UNRESOLVED");
    event.setTriggerTime(LocalDateTime.now());
    event.setRemark(remark);
    sosEventMapper.insert(event);

    // 2. 联动生成初始紧急服务工单 (直接进入待派单状态)
    WorkOrder order = new WorkOrder();
    order.setOrderNo("EMG" + System.currentTimeMillis() + UUID.randomUUID().toString().substring(0, 4));
    order.setOrderType("EMERGENCY");
    order.setCommunityId(elder.getCommunityId());
    order.setElderId(elderId);
    order.setElderName(elder.getFullName());
    order.setAddress(elder.getAddress());
    order.setPhone(elder.getPhone());
    order.setStatus("PENDING_DISPATCH");
    order.setEmergencyEventId(event.getId());
    order.setVersion(0);
    workOrderMapper.insert(order);

    // 3. 异步触发事件广播 (社区大屏报警与子女通知)
    eventPublisher.publishEvent(new EmergencyAlarmEvent(this, event, order));
    return order;
}
```

### 5.1.3 子女端多维体征趋势与代预约实现

子女登录后，进入监护工作台，系统提供双向监护能力：
1. **多维体征动态趋势图**：子女切换查看收缩压/舒张压与静息心率走势，基于前端图表平滑绘制折线图，对超过正常范围的峰值数据标红高亮并给出健康生活指导建议；
2. **助老服务在线代预约**：子女选择服务大类（助洁、助医等）、设定期望到访日期，填写老人近期生活禁忌并提交。后端生成 `service_reservation` 记录，由社区管理员统一审核并转化派发。

## 5.2 线下履约端功能实现

系统为网格员与社区专业护工开发了专属的移动端履约模块，提供纯净的任务处理流。

### 5.2.1 护工专属工单列表与状态更新实现

#### 1. 护工权限隔离查询
在 `WorkOrderServiceImpl.java` 中，系统严格限制护工仅能拉取指派给本人的任务：
```java
@Override
public List<WorkOrderVO> listCareWorkerOrders() {
    CurrentUser current = authorizationPolicy.requireCurrentUser();
    // 强制断言当前角色并构建受限上下文
    CareWorkerScope scope = requireCareWorkerScope(current);

    LambdaQueryWrapper<WorkOrder> query = new LambdaQueryWrapper<>();
    query.eq(WorkOrder::getAssignedTo, current.getUserId())
         .notIn(WorkOrder::getStatus, CARE_WORKER_TERMINAL_STATUSES)
         .orderByDesc(WorkOrder::getDispatchedAt);

    List<WorkOrder> list = workOrderMapper.selectList(query);
    return convertToCareWorkerVOList(list);
}
```

#### 2. 接单与任务启动
护工收到新工单通知后，点击“确认接单”，状态机将工单由 `DISPATCHED` 推进至 `ACCEPTED`；护工到达老人家中后，轻触“开始服务”，工单推进至 `IN_PROGRESS`，同时记录接单与上门时间戳。

### 5.2.2 现场服务处置与照片证据上传实现

#### 1. 照片文件上传与哈希存证
护工调起系统相机完成现场照护拍照，前端通过多部分表单（`multipart/form-data`）提交至 `FileUploadController`。系统校验文件 MIME 类型为图片并限制大小 $\le 5\text{MB}$，计算 SHA-256 文件哈希值，持久化至 `work_order_photo_evidence` 表中。

#### 2. 服务结案提交与强约束校验
服务完成后，护工录入简短的处置总结，点击“提交审核”。后端严格校验照片数量：
```java
@Override
@Transactional
public void submitOrderExecution(Long workOrderId, WorkOrderExecutionDTO dto, Long operatorId) {
    WorkOrder order = workOrderMapper.selectById(workOrderId);
    assertStatus(order, "IN_PROGRESS");
    requireCurrentAssignee(order, operatorId);

    // 强约束校验：必须存在合法关联的现场照片凭证
    int evidenceCount = photoEvidenceMapper.selectCount(
        new LambdaQueryWrapper<WorkOrderPhotoEvidence>()
            .eq(WorkOrderPhotoEvidence::getWorkOrderId, workOrderId)
    );
    if (evidenceCount < 1) {
        throw new BusinessException(ErrorCode.EVIDENCE_MISSING, "必须上传至少一张服务现场照片方可提交");
    }

    // 状态流转推进至待审核
    order.setStatus("SUBMITTED");
    order.setSubmittedAt(LocalDateTime.now());
    order.setExecutionNotes(dto.getNotes());
    workOrderMapper.updateById(order);

    // 记录工单流转动作历史
    recordActionHistory(order.getId(), "SUBMIT_REVIEW", operatorId, "护工完成现场服务并提交审核");
}
```

## 5.3 社区综合管理端功能实现

社区 Web 后台以 Vue 3 + Element Plus 构建，是社区养老服务的核心指挥中枢。

### 5.3.1 老人档案管理与亲情绑定核验实现

1. **档案建档与激活码生成**：
   社区工作人员线下核实老人居住地址与身份证信息后，录入系统生成 `elder_profile`。针对无智能手机或不能自行注册的老人，管理员点击“生成激活码”，系统生成唯一的 6 位数字激活码并设定 24 小时过期时间，便于老人当面激活身份绑定。
2. **亲情关系人工审核**：
   管理员在“亲情绑定审批”板块查看子女提交的申请，系统展示申请人手机号、亲属关系陈述及老人当前健康状况。管理员电话核验老人真实意愿后，点击“批准绑定”，状态即刻生效。

### 5.3.2 社区网格化派单与工单审核结案实现

#### 1. 调度中心派单实现
进入“工单调度中心”，列表展示当前社区待处理工单（`PENDING_DISPATCH`）。管理员点击“派单”，弹出对话框调用接口获取本社区护工列表，列表显示每个护工当前待办单数。管理员选定护工后提交，后端通过行级乐观锁执行派发并更新版本号：
```java
int updated = workOrderMapper.update(null,
    new LambdaUpdateWrapper<WorkOrder>()
        .set(WorkOrder::getStatus, "DISPATCHED")
        .set(WorkOrder::getAssignedTo, dto.getAssigneeUserId())
        .set(WorkOrder::getDispatchedAt, LocalDateTime.now())
        .set(WorkOrder::getVersion, order.getVersion() + 1)
        .eq(WorkOrder::getId, order.getId())
        .eq(WorkOrder::getVersion, order.getVersion()) // 乐观锁版本匹配
);
if (updated == 0) {
    throw new BusinessException(ErrorCode.CONCURRENT_CONFLICT, "工单状态已变更，请刷新后重试");
}
```

#### 2. 审核结案弹窗实现
管理员点击处于 `SUBMITTED` 状态的工单，系统弹窗展示护工上传的现场服务照片（支持点击全屏放大预览）与服务文字报告。管理员确认无误后点击“审核通过”，工单正式归档（`CLOSED`），自动记录结案时间并同步通知家属端。

### 5.3.3 社区运营与预警处置时效看板实现

社区管理大屏依托 ECharts 实现实时态势感知：
- **实时指标磁贴**：展示在册老人总数、高风险慢病老人数、待处置告警数；
- **健康告警分类占比**：以环形图展示突发 SOS、高血压异常、心率过速的构成比例；
- **工单响应时效走势**：以柱状折线复合图展示近 7 日从“建单”到“护工首次接单”的平均响应时长（控制在 10 分钟以内）与结案满意率。

### 5.3.4 仿真环境与异常数据发生器实现

针对日常应急演练与系统测试需要，管理端开发了 **IoT 数据仿真控制台**：
- 支持选择指定老人档案与体征指标类型（收缩压、舒张压、血糖、心率）；
- 支持注入典型异常预置模板（如“急性高血压发作场景”、“低血糖晕厥场景”）；
- 后端后台守护线程按设定频率自动产生模拟数据上报，从而全链路检验健康规则引擎评估、告警触发、社区自动报警与派单闭环的健壮性。
