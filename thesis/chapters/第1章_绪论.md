# 第 1 章 绪论

## 1.1 研究背景与实际需求

随着人口老龄化进程的不断加快，如何构建高质量、可持续、全覆盖的养老服务体系，已成为我国经济社会发展面临的重大战略课题。国家卫生健康委员会于 2021 年新闻发布会明确指出，当前我国养老格局呈现典型的“9073”特征，即约 90% 的老年人选择居家养老，约 7% 的老年人依托社区支持养老，仅有约 3% 的老年人入住机构养老。这一格局决定了以家庭为核心、以社区为依托的“社区居家养老服务模式”，是解决我国规模化养老照护需求的根本途径。

然而，在当前的社会现实中，社区居家养老面临着严峻的“照护资源断层”矛盾：一方面，独居老人、高龄空巢老人及慢性病失能老人的规模持续扩大，日常健康监测、按时服药管理以及突发疾病的应急求助需求极其迫切；另一方面，其子女大多异地就业或忙于工作，难以提供全天候的现场照护，传统的家庭看护模式日趋弱化。

国家高度重视智慧养老服务与适老化信息基础设施的建设。《中华人民共和国无障碍环境建设法》于 2023 年 9 月正式施行，从法制层面明确了保障老年人、残疾人等群体平等便捷接入数字信息服务的要求。工业和信息化部办公厅发布的《关于进一步抓好互联网应用适老化及无障碍改造专项行动实施工作的通知》（工信厅信管函〔2021〕67 号），明确制定了《移动互联网应用（APP）适老化通用设计规范》，对移动界面的正文字号、可点击热区、色彩对比度以及防误触机制提出了明确的量化标准。

在此背景下，借助新一代信息技术，研发一套既符合国家适老化交互标准，又能高效联动老年人、监护子女、社区工作人员与专业护工的智慧社区居家养老服务系统，具有极为迫切的现实需求。

## 1.2 研究目的与意义

### 1.2.1 实践意义

1. **破除老年“数字鸿沟”，实现无障碍自助服务**：传统智慧养老客户端界面繁琐、文字偏小、弹窗诱导泛滥，老年人常因操作畏惧而“不敢用、不会用”。本系统以适老化国家规范为指导，提供大字大图标、高对比度、单向导航和语音辅助引导的老人模式，帮助老人轻松完成日常服药打卡、健康自查与一键 SOS 紧急呼救，让数字技术真正惠及银发群体。
2. **打通家庭与社区协同，实现线下服务闭环履约**：系统构建了“老人受助 $\to$ 子女监护代办 $\to$ 社区统筹调度 $\to$ 护工网格履约 $\to$ 证据链审核”的全链条业务闭环。异地子女可远程掌握父母健康状况并代为预约助餐、助医等服务；社区根据网格化属地原则派单，护工上门服务并上传现场照片存证，彻底改变以往居家养老“线上派单易、线下监督难、服务走过场”的混乱局面。
3. **沉淀规范工程基座，支撑基层精准治理**：系统采用 Spring Boot 3 与模块化单体分层架构，结合 Flyway 数据库迁移和轻量级权限隔离，无需高昂的分布式集群运维成本即可在普通社区服务器或云主机平稳部署，为基层社区养老服务机构提供了一套开箱即用、低成本、高可靠的数字化治理底座。

### 1.2.2 理论意义

1. **认知负荷理论在老年人机交互中的工程落地**：结合认知心理学领域的认知负荷理论（Cognitive Load Theory），系统深入分析了老年人在感知觉退化与工作记忆容量衰减条件下的信息处理特征，探索了如何通过削减“外在认知负荷”（Extraneous Cognitive Load）实现界面自适应简化，丰富了适老化人机交互工程的量化设计方法。
2. **多角色与多租户协同下的网格化状态流转模型**：系统形式化定义了社区居家养老服务的有限状态机（FSM）模型与属地数据权限隔离策略，解决了异地监护权（亲情关系）、属地管理权（社区管理员）与现场处置权（本人分配工单）三者交织下的并发控制与越权防护难题，为同类社会治理服务系统的架构设计提供了理论借鉴。

## 1.3 国内外研究现状

### 1.3.1 智慧社区养老系统国内外研究现状

在国际上，欧美日等较早进入老龄化社会的国家在智慧养老领域开展了大量探索。西方国家学者偏向于利用物联网（IoT）传感器、可穿戴设备和智能家居构建远程健康监护平台。然而，国外系统大多依赖昂贵的专业医疗硬件，且高度依赖成熟的商业养老机构或全科家庭医生网络，难以直接平移至我国以公办社区治理和家庭子女监护为主体的“9073”国情环境。

在国内，随着“互联网+养老”战略的推进，高校与产业界陆续开发了多种社区养老信息平台。国内现有研究多聚焦于 Spring Boot、微服务与大数据技术的整合应用，实现了老人健康档案管理、体征数据可视化和生活服务商城等基础功能。但从实际运行效果来看，大多数系统偏向于静态的信息展示与数据录入，在面对老年人突发重疾求助、线下服务人员派单调度与履约证据核查等动态业务链条时，缺乏完整的状态机流转控制与权责审计体系。

### 1.3.2 适老化人机交互与认知负荷研究现状

在人机交互（HCI）领域，针对老年群体的交互设计正在由早期的“经验性放大界面”转向“基于心理学与人体工学的严谨设计”。Sweller 等人提出的认知负荷理论指出，人类工作记忆容量极其有限，复杂的层级嵌套和杂乱的信息排版会急剧消耗外在认知负荷，导致老年人产生认知超载。近年来，学者通过眼动实验与可用性测试证实，加大按钮间距、采用无衬线高对比度字体、消除多任务分支路径，能显著提升老年用户的操作完成率并降低误触率。然而，当前多数智慧养老软件在开发过程中仍以年轻用户的交互习惯为主导，老人端适老化功能缺乏系统的标准参照与量化测试评价。

### 1.3.3 现有研究评述与研究缺口

综合分析国内外现有研究成果，当前社区居家养老系统的研究与实现仍存在以下三项关键缺口：
1. **缺口一：重健康数据采集展示，轻线下服务调度与履约闭环**。现有系统往往止步于展示体征折线图和告警提示，缺乏从异常触发到社区工单指派、护工接单、上门处置、现场存证到管理审核的严格业务闭环，导致线上预警与线下救助脱节。
2. **缺口二：适老化改造流于形式，缺乏认知理论支撑与量化验收**。许多平台仅仅在界面上提供一个“长辈模式”放大文字，未重构操作链路，缺乏对工信部适老化规范和认知负荷理论的系统贯彻，老人依然无法独立完成核心操作。
3. **缺口三：多方主体协同下的数据安全与权限边界不明确**。养老系统涉及老年人、监护子女、网格员和社区管理员四类主体，老人健康与病历属于高敏感隐私。现有系统往往采用粗粒度的角色权限控制（RBAC），缺乏对亲情绑定授权范围、护工本人分配工单限制及社区属地数据隔离的细粒度约束，存在较大的越权访问隐患。

本课题正是在针对上述三大缺口的深入思考下，确立了设计与实现方案。

## 1.4 主要研究内容与方法

### 1.4.1 主要研究内容

1. **面向多角色的适老化交互体系设计与实现**：基于 Uni-app 跨端框架构建移动端双模式，老人模式严格遵从认知负荷理论削减外在负荷，实现大字图文、一键呼救和语音辅助引导；子女模式提供健康趋势监护、用药提醒计划制定与助老代预约。
2. **基于网格化与有限状态机的工单流转与调度机制研发**：针对普通预约与突发 SOS 两类事件源，抽象出统一的社区工单模型；利用有限状态机严格约束工单生命周期状态流转；结合行级乐观锁化解多人并发调度冲突；引入现场照片证据链保证线下服务真实可信。
3. **基于属地多租户与动态授权的权限边界架构设计**：在 Spring Boot 3 框架下实现社区管理员属地隔离、子女亲情授权验证及护工专属工单动态受权，构建全方位的数据安全防护网。
4. **系统工程化落地与质量实证评估**：完成覆盖 12 个业务模块的工程化实现，利用 Flyway 进行平滑数据库版本治理；构建涵盖功能性、权限边界、并发防竞态与性能吞吐量的全套自动化测试用例，验证系统的高可靠性。

### 1.4.2 研究方法与技术路线

本研究采取“规范标准指导、理论模型驱动、工程实证验证”的技术路线：
1. **文献调研与标准对标法**：深入研读《中华人民共和国无障碍环境建设法》、工信部 67 号文规范及认知负荷理论核心著作，确立系统功能边界与适老化设计判据。
2. **面向对象与状态机建模法**：采用 UML 工具对四类核心角色进行用例建模与时序梳理；利用形式化状态机对工单流转状态进行严格建模与矩阵定义。
3. **前后端分离工程开发法**：后端依托 Spring Boot 3、MyBatis-Plus 和 MySQL 8.0 构建高内聚低耦合的单体分层后端；移动端依托 Uni-app + Vue 3 交付微信小程序；Web 管理端依托 Vue 3 + Element Plus 构建响应式管理工作台。
4. **自动化测试与实证分析法**：通过隔离环境下的自动化单元测试、API 集成测试、浏览器端端 Smoke 测试与高并发压力测试，对系统可用性、数据隔离性与抗并发能力进行量化检验。
